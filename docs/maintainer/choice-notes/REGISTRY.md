# Реестр моделей v2 — схема (25.10, упрощённая по замечанию владельца)

Один JSON, подписанный ключом релиза (DECISIONS 31): сервер → кэш → копия в установке. Заполняем мы;
программа у клиента только читает. В нём только то, что программа использует и не может узнать сама.

```json
{
  "version": 113,
  "models": {
    "qwen3.5-9b": {
      "drafters": {
        "mtp":    { "e": [1.9, 2.6, 3.2, 3.6, 3.9] },
        "dflash": { "repo": "z-lab/Qwen3.5-9B-DFlash@5fc3b3d4", "e": [1.9, 2.6, 3.2, 3.6, 3.9, 4.2, 4.3] }
      },
      "variants": {
        "unsloth/Qwen3.5-9B-GGUF@a1b2c3d4": {
          "drafters": ["dflash"],
          "files": { "Q4_K_M": "Qwen3.5-9B-Q4_K_M.gguf", "Q8_0": "Qwen3.5-9B-Q8_0.gguf",
                     "mmproj": "mmproj-F16.gguf" }
        },
        "unsloth/Qwen3.5-9B-MTP-GGUF@e5f6a7b8": {
          "drafters": ["mtp", "dflash"],
          "files": { "Q4_K_M": "Qwen3.5-9B-Q4_K_M.gguf" }
        }
      }
    }
  }
}
```

- `e` — токены за раунд для глубин 1, 2, 3, … (смешанная нагрузка): выбор глубины и ускорение (E/R).
- драфтер с `repo@commit` скачивается отдельно; без `repo` — он в весах модели.
- `drafters` варианта — какие драфтеры подходят этому файлу.
- `files` — роль каждого файла: квант (по метке) или проектор (`mmproj`) — вместо угадывания по имени.
- коммит в `@` фиксирует содержимое; размеры даёт хаб при планировании.

Не в реестре (наш лабораторный журнал, клиенту не нужно): E по видам задач, карты и даты замеров,
корпус, разброс, лицензии, названия, семейство (читается из модели).
