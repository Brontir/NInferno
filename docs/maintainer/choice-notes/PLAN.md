# Единый выбор конфигурации NInferno — план

## Главная цель (сверяться на каждом шаге)

Слова владельца, по смыслу:
1. Один прозрачный код выбора (память / скорость / точность из фактов) для всех мест: сервер, CLI, план, GUI.
2. При почти равной цене по умолчанию побеждает качество. Это явная зависимость (λ), понятно, где она и как работает.
3. Человек в GUI видит, что изменится, если он поменяет входы или переключатели.
4. Старый непрозрачный код вычищен.
5. Данные — из замеров. Когда всё готово — перемерить.
6. Спорное записано в DECISIONS.md.
7. Проверка на непромеренных комбинациях, на смеси задач.

Цель: один код, который по фактам модели, фактам карты и задаче пользователя считает три опоры
(память, скорость, точность) и выбирает конфигурацию детерминированно, без замеров на машине
пользователя. Тот же код показывает человеку, что изменится, если он поменяет вход или переключатель.
Им пользуются все места, где нужен такой выбор: CLI, сервер (`ninferno-serve` без флагов), план без
весов (`--plan --no-load`), GUI (`/api/plan`, `/api/quants`, каталог).

## Что уже есть (на чём строим)

- **Память — точная.** PR #60 разработчика (`det/plan-no-load`): план без весов. Байты каждой ступени
  считают байтовые функции самого планировщика семейства; лестница и её выбор — те же функции, что при
  старте. На нём сейчас стоит правило «самый крупный квант, что влезает» (`quant_rule.h`).
- **Факты карты.** `GpuKey` (частота, полоса, число SM), `core/generation.h` (пики BF16/INT8 на SM за такт
  по поколениям), `gpu_facts.json`.
- **Скорость спекуляции.** `spec/load_model.h` (модель раунда проверки) и профили реестра.
- **Замеры** на 4 стендах: скорость по переключателям (9B, 27B, 35B-A3B), точность по переключателям
  (9B, ninferno-perplexity). Кривая по квантам и состояние под fast считаются на 5070 Ti.

## Модель выбора

1. **Вход.** Модель (факты из config/GGUF), карта (факты по PCI ID, свободная память), задача: контекст
   на поток, число потоков C, форма запроса (длина промпта P и ответа G). Плюс явные флаги — они
   закрепляют свои оси.
2. **Кандидаты.** Квант × KV × активации × чанк × снимки K (кольцо и состояние следуют из KV по
   правилам владельца, их можно закрепить флагом).
3. **Отсев.** Нужный контекст × C не влезает (точная память из плана #60) — кандидат отпадает.
   Маршрут не поддерживается (FP4 не на Blackwell, int8-активации не у Qwen, exact с f16-состоянием) —
   тоже.
4. **Три оценки** для каждого оставшегося:
   - память: контекст на поток (ctx_max) и запас;
   - скорость: время типового запроса T = P/prefill + G/decode;
     - декод = C / (чтение весов и KV / (η_d · полоса) + вычисления / (η_c · пик)) × ускорение спекуляции;
     - префилл = η_p · пик / (2 · активные параметры);
     - η — по поколению карты и типу модели (плотная / MoE), из замеров на стендах;
   - точность: KLD к эталону, корень из суммы квадратов слагаемых (квант, KV, состояние, активации, кольцо).
5. **Одна формула полезности:** U = −ln T − λ · KLD.
   - λ — единственный параметр «цена точности»: сколько скорости стоит 0,001 KLD.
   - По умолчанию λ смещён к качеству: при почти равной скорости побеждает точность.
   - Без замера слагаемого точности кандидат не считается точнее известного.
6. **Ничья** (|ΔU| < ε): больше запас контекста, затем меньше памяти, затем порядок кандидатов. Порядок
   полный и однозначный.
7. **Объяснение.** Для выбранного кандидата по каждой оси показываются соседние значения и что они
   меняют: контекст, декод, префилл, KLD, U. Для входов (контекст, C, карта) — тот же пересчёт.
