# Разбор алгоритма выбора (28.10)

Взгляд с нескольких сторон: насколько он простой, прозрачный и качественный, что не готово, как он
стыкуется с GUI и с консолью, что стоит переосмыслить и о чём поговорить с владельцем. Факты сверены
с кодом веток master, `det/choice-drafter-axis` (S3) и `det/engine-support-truth` (#114).

## 1. Как он устроен сейчас (одной картинкой)

```
факты модели + факты карты + задача (контекст, потоки, рассуждения)
        │
        ├─ память   : план без весов (функции семейства), свой контекст на поток
        ├─ скорость : модель шага (choice_constants) × ускорение драфтера (замер пары / группа)
        └─ точность : KLD-слагаемые (квант, KV, состояние, активации)
        │
   кандидаты = квант × KV × активации × драфтер (× чанк у MoE)
   годен, если держит цель контекста (Авто: 32K → 16K → 8K на поток)
   побеждает max( −ln T − λ·KLD ),  λ = 25  (0,001 KLD = 2,5 % времени запроса)
        │
   explain(): у каждой оси — почему соседнее значение проиграло
```

Ядро (`src/product/choice`) — около 800 строк, чистое: без CUDA, файлов и часов. Его зовут сервер,
план без весов и GUI.

## 2. Простота и прозрачность

**Хорошо.**
- Одно ядро и одна формула ценности. λ — явная константа с объяснением в одну строку.
- Каждое решение объясняется по осям: квант, KV, активации, драфтер, чанк.
- Детерминизм: решение зависит только от фактов, без замеров на машине пользователя.

**Плохо (сложность вокруг ядра, а не в нём).** Вокруг ядра много слоёв, частью старых:
- правило квантов с ярусами (наибольший влезающий, порог 4 бит), и поверх него та же ценность;
- порядок старта спекуляции: свой откат, мельче, MTP-голова, правило пула;
- старые профили спекуляции и всё, что их обслуживает:
  - `*`-профили, «похожая карта», `served`, `portable`;
  - модель цены раунда и классы контекста — они только показываются и ни на что не влияют;
  - таблицы нагрузки;
- новые пары и группы (S1–S3) идут параллельно со старыми профилями.

Пока старое не снесено (S4), человеку трудно понять, откуда взялась цифра. Строки «depth 0 (no
estimate)» в выводе — именно отсюда.

## 3. Качество

- **Скорость:** модель шага в замерах — rms 5,3 %, худшее 15,5 %. Ускорение драфтера взято из
  замера пары на контексте 4096 и одном потоке; поправка на длину контекста ≤ 6 %.
- **Точность:** слагаемые KLD есть только у Qwen 3.5 / 3.6 и dense (Qwen3-8B). У Gemma KLD на
  порядки больше, и в одной валюте с Qwen он несравним (DECISIONS 41). Привязка KLD к ложным
  ответам ещё не сделана: отбор вопросов есть, повторы идут.
- **Главная дыра — поколения карт.** Решать по ценности разрешено только там, где есть опорная
  карта поколения с константами, снятыми на двух картах. Сейчас это только **Ada** (4070 Ti и
  4090). На Blackwell (5070 Ti/5080/5090), Turing и Ampere выбор берёт умолчания семейства: KV,
  активации и драфтер профиля. Ценность там не решает: «gb20x has no reference card».

## 5. Стык с GUI

- GUI зовёт то же ядро через `/api/plan`, и для каждой строки квантов — свой выбор.
- **Расхождения, найденные сейчас:**
  1. **Скорости в таблице квантов GUI без драфтера.** Оценка строки (`plan_quants`,
     `choice::speed_of`) строится по кандидату без драфтера, а выбор для той же строки драфтер
     учитывает. В таблице ток/с без спекуляции, в выборе — с ней.
  2. **Ось драфтера в объяснениях GUI не подписана**: нет перевода `ax_drafter`, на экран попадёт
     сырой ключ. Строка выбора показывает KV / активации / состояние, но не драфтер.
  3. **GUI запускает GGUF без `--with-drafters`.** У Gemma GGUF никогда нет ассистента, у Qwen GGUF
     без встроенного MTP — нет DFlash. Сервер с флагом выбрал бы иначе.
  4. **Память отдельного драфтера GUI берёт другим путём**: из `speculation_json` реестра, а сервер —
     по листингу репозитория драфтера и его config.json. Это два кода для одного числа.
- Переключатель рассуждений и дельта к другому варианту (по вашему слову) — не сделаны.

## 6. Стык с консолью

- **`ninferno-serve` без флагов:** применяет выбор целиком — KV, активации, состояние, кольцо, чанк,
  а теперь и драфтер (S3). Явный флаг закрепляет свою ось.
- **`ninferno-serve --plan --no-load`:** показывает тот же выбор и почему. С S3 план показывает
  драфтер выбора.
- **CLI `ninferno`:** применяет только KV / активации / состояние / кольцо. Драфтер и чанк
  остаются из профиля и флагов: CLI не следует оси драфтера. Это третье место, где выбор применяется
  не целиком.
- `--draft-tokens 5:4` пока нет.

## 7. Что стоит переосмыслить

1. **Убрать два порядка (ярусы правила квантов и ценность), оставить один.** Наибольший влезающий
   квант нужен только там, где ценность не решает. Если дать опорные константы всем поколениям,
   ярусы останутся только для «ниже 4 бит».
2. **Опорная карта на поколение.** Сейчас Ada решает за всех, а Blackwell — ничего. Либо снимать
   константы на двух картах каждого поколения (лаборатория: нужна вторая Blackwell), либо разрешить
   перенос констант между поколениями с поправкой по характеристикам чипа и пометкой «перенесено».
3. **Снести старое (S4) — сразу после кампании пар**, а не держать два мира: опубликованные
   профили, `served`, модель цены раунда, классы контекста.
4. **Одна функция памяти драфтера для сервера, GUI и CLI.**
5. **Точность в одной валюте для всех семейств — через ложные ответы**, а не через KLD.

## 8. Что проговорить с владельцем

1. **λ = 25 на примере.** На 12 ГБ: Q8_0 без драфтера (точнее, медленнее) против Q5 + DFlash
   (×2,5 быстрее, KLD выше). Сейчас выбор берёт Q5 + DFlash. Это то, что вы хотите от «качество при
   почти равной цене»? Здесь цена не почти равная — в 2,5 раза.
2. **Blackwell и другие поколения без опорной карты.** Покупать или занимать вторую Blackwell для
   констант, или разрешить перенос с Ada с пометкой?
3. **Драфтеры без замера** (MTP-голова, встроенный дефолт): «нет данных — не предлагаем» или
   «встроенный MTP по умолчанию считаем выгодным»?
4. **GGUF и `--with-drafters` по умолчанию** (будет DECISIONS 45): подключать драфтер, когда выбор
   его выбирает, — с докачкой сотен МБ – 2,4 ГБ?
5. **Цель контекста в «Авто»: 32K на поток.** Подходит ли как «нужный контекст», или для
   рассуждений нужна больше?
6. **CLI `ninferno`**: должен ли он применять выбор целиком, как сервер?
