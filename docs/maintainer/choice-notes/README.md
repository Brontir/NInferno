# Единый выбор конфигурации — что сделано

Движок сам выбирает конфигурацию по фактам модели, карты и задачи, без замеров на машине пользователя:
квант, тип KV, активации, состояние, кольцо окна и чанк. Код один для сервера, CLI, плана без весов
и GUI. Он объясняет, что изменит каждое другое значение.

**Статус на 24.10:** на Ada (RTX 4070 Ti, 4090) выбор работает в продукте полностью. Это проверено
на настоящем старте, в GUI и на реальных замерах. По дороге найден и исправлен дефект движка, из-за
которого режим `fast` на половине карт терял точность в 7,6 раза (PR #91).

## Как устроено

1. **Память** — точная: план без весов из #60, каждый кандидат на «простаивающей» карте.
2. **Скорость** — формула от фактов карты и модели. Константы подогнаны по стендам. На реальных
   задачах ошибка ±5–13 % на четырёх картах.
3. **Точность** — измеренный KLD каждого переключателя и кривая по квантам. Всё снято на двух картах
   двух поколений. Кривая совпала в 8 точках из 8 с расхождением ≤ 2 %.
4. **Выбор** — одна формула: полезность = −ln(время запроса) − 25·KLD. При почти равной цене
   побеждает точность.
5. **Правило проекта:** решения считаются на «эталонной карте поколения», и решают только константы,
   снятые на двух картах.
   - Сейчас решает Ada.
   - На Blackwell и Turing остаются умолчания семейства: там по одной карте.
   - Решает только семейство, на котором сняты замеры (Qwen 3.5 dense).

## Главное за последние сутки

- **Найден дефект движка (#91).** ggml MMQ (префилл K-квантов на 4090, 4070 Ti, 2080 Ti, 5090 и др.)
  считал сумму блока по исходным активациям, а скалярное произведение — по квантованным.
  - Для Q4_K/Q5_K и других форматов с «минимумом» это давало KLD 0,030 вместо 0,004, top-1
    95,8 % вместо 98,5 %.
  - Исправление в одну строку, скорость та же. Проверено на трёх картах и трёх моделях, ctest
    270/270 на двух поколениях, регрессионный тест с FP64-оракулом.
- **Выбор на Ada решает в продукте.** Для Qwen3.5-9B:

  | Карта | Что выбрано | Самый крупный, что влезает |
  |---|---|---|
  | 4070 Ti | UD-Q5_K_XL, fast, KV int8 | Q8_0 |
  | 4090 | то же | UD-Q8_K_XL |

  Выбор одинаков на обеих картах — так работает эталонная карта поколения.
- **Доказательство на реальных замерах** (4090, смесь задач). Выбор движка отстаёт от лучшей
  измеренной конфигурации (Q6_K fast) примерно на 4 % времени запроса — практически ничья. Самый
  крупный квант (Q8_0) хуже: на 26 % дольше ради 0,005 KLD.
- **GUI проверен вживую на Ada.** Звёздочка у выбранного кванта, подпись «Лучший баланс скорости и
  точности», таблица «что изменится» по каждой оси.

## Где нужно твоё решение

- **λ = 25 и выбор кванта по полезности (DECISIONS 18).** Сейчас для 9B на Ada берётся средний
  квант, а не самый крупный, что влезает. Если хочешь чаще крупные кванты, нужно поднять λ.
- **Слагаемые точности для других семейств (DECISIONS 22).** Пока по ним не решаем. Нужен замер
  перплексии хотя бы для Gemma 4 и Qwen-MoE.
- **Слияние #60 разработчика** — без него цепочка #88–#90 не вливается. #91 можно вливать отдельно.

## Рекомендованный следующий шаг (вне этой задачи)

Сейчас по полезности решают только семейства Qwen 3.5: dense полностью, MoE — без кванта.
- Чтобы решали Gemma 4, dense-декодеры и Nemotron-H, нужно снять их слагаемые точности (KLD).
- Для этого `ninferno-perplexity` должен уметь их оценивать: режим `CausalScoring` в программах этих
  семейств, логиты по всем позициям окна.
- Это работа в программах моделей, то есть зона разработчика. Я её не начинал.
