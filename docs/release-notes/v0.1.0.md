# NInferno 0.1.0: what to know

The first release. This page lists behavior worth knowing if you come from another server or from
an earlier build. Flags and defaults are in [serving](../serving.md) and the
[reference](../reference/serving.md).

## Requests and API

- **`tool_choice: "none"`** keeps the tool declarations in the prompt (so the cached prefix is
  reused), but the model can no longer answer with a call. Before, the model could still write a
  call, which was cut out and left an empty reply or markup in the text. Now three things act
  together ([#546](https://github.com/Brontir/NInferno/pull/546)):
  - the call opener is banned for the Qwen, Hermes, Gemma 4, Mistral, Granite and Pythonic
    templates;
  - the last user turn (after a tool result, the end of that result) ends with the line `Tools are
    unavailable for this reply; answer in plain text.` It counts in the prompt tokens. A Messages
    request that ends with an assistant prefill gets no such line;
  - other structural tokens (`</think>`, a tool-response marker) no longer reach the answer or loop,
    and a bare JSON call that opens the answer is cut, also one with `id` or `type` before its
    name ([#592](https://github.com/Brontir/NInferno/pull/592)).

  `--tool-choice-none drop-tools` sends no declarations at all instead (the prompt is prefilled
  again). On gpt-oss (Harmony) the prompt steers the message header away from a call, and a message
  to any recipient is cut ([#582](https://github.com/Brontir/NInferno/pull/582),
  [#604](https://github.com/Brontir/NInferno/pull/604),
  [#672](https://github.com/Brontir/NInferno/pull/672)). On gpt-oss-20b (MXFP4) on an RTX 5090,
  greedy, 8 prompts that ask for a tool, empty answers went from 5 of 8 to 1 of 8 at
  `max_tokens` 200 and from 4 of 8 to 0 of 8 at 1000. On Llama 3 JSON a written call is still cut
  from the answer, as before.
- **A forced call (`tool_choice` required or named) cut by a stop string** is dropped, and the
  complete calls before it are kept. Before, its markup came back as text
  ([#545](https://github.com/Brontir/NInferno/pull/545)).
- **A tool-call turn cut by `max_tokens`, the context or a repetition loop** no longer reports
  `finish_reason: tool_calls` (Messages: `tool_use`). Chat answers `length` and Messages answers
  `max_tokens` (`model_context_window_exceeded` when the context ran out), so a client can tell the turn was cut. The complete calls stay in the body
  ([#555](https://github.com/Brontir/NInferno/pull/555)).
- **gpt-oss tool loops:** the reasoning of an earlier tool-call turn now reaches the template
  (`thinking` as well as `reasoning_content`; Chat accepts `thinking` as an alias), so the model
  keeps its plan. In the report's calculator request on an RTX 4060 Ti the answer went from 110
  tokens without a call to 34 tokens with the call
  ([#557](https://github.com/Brontir/NInferno/pull/557)). The model's own call turn is also
  a cache boundary, so step 2 of a tool loop can reuse the prefix (checked in the frontend
  test; no live measurement) ([#577](https://github.com/Brontir/NInferno/pull/577)).
- **Tool order:** tools render in the order the request gives them. Before, the first order seen
  for a set of names was remembered, so the same request could give different prompts depending on
  which client came first. `--tool-order sorted` renders every order of one set sorted by name, for
  clients whose MCP servers register in varying order; a request with a duplicate tool name or a
  cache boundary after a tool keeps its own order
  ([#533](https://github.com/Brontir/NInferno/pull/533)).
- **Responses:** a `previous_response_id` the store no longer has (after a restart, an eviction, a
  delete) is 400 `previous_response_not_found`, the shape OpenAI clients retry on with the full
  input; before, it was 404
  ([#531](https://github.com/Brontir/NInferno/pull/531)). The serving reference now lists what
  Responses accepts: `json_schema` and `json_object` text formats, `required` and named
  `tool_choice`, `allowed_tools`, `parallel_tool_calls: false`
  ([#530](https://github.com/Brontir/NInferno/pull/530)).
- **`logit_bias` of `-100` is a ban** (Chat Completions only): the token loses to every token that
  is not banned. Offsets are in `[-100, 100]`, a token id past the vocabulary is a 400, and a bias
  of your own on a token the server bans (a call opener under `tool_choice: "none"`) is replaced by
  the ban.
- **Qwen3.6 templates, thinking off:** a request with thinking off and no reasoning in its history
  now keeps the empty think blocks of earlier assistant turns, so an agent session that adds a user
  message after many tool turns keeps its cached prefix. To get the template's own rendering back,
  send `preserve_thinking: false` or start with `--no-preserve-thinking`.
- **Regex and JSON Schema `pattern` constraints:** an optional group no longer lets its tail
  through without its head. `^[0-9]+\.[0-9]+(-[a-z]+)?$` let the model write `1.2rc`; such strings
  can no longer be generated. A second fix stops some valid tokens from being wrongly excluded.
- **Tokenizer:** the pre-tokenizer reads Unicode 16 categories, as Hugging Face `tokenizers` does.
  Code points that Unicode 17 assigned were letters for NInferno and unassigned for `tokenizers`,
  so the split next to contractions and `_` differed
  ([#559](https://github.com/Brontir/NInferno/pull/559)).
- **`--activations fast`:** byte equality between chunk sizes holds only with BF16 activations. With
  int8 activations the guarantee holds only when the 512-token slices of the prompt are cut at the
  same positions: on an RTX 4060 Ti, Qwen3-8B Q4_K_M, chunks of 1024 and 1536 gave identical
  logprobs, 768 and 384 differed by up to 0.131. Use `--activations exact` for byte equality
  ([#493](https://github.com/Brontir/NInferno/pull/493)). On NVFP4 MLP projections `fast` also
  takes a different kernel at 1 row, at 2 to 8 rows and from 12 rows, so a batched candidate and
  its reference can rank close tokens differently; that is by design, not a defect
  ([#571](https://github.com/Brontir/NInferno/pull/571)).

## HTTP

- **An HTTP/1.1 request without a `Host` header gets 400** and the connection closes. Two `Host`
  headers or an invalid one are refused in any version.
- **A warning at start** when the server listens on a non-loopback address without an API key.
  Nothing is refused; pass `--api-key-file` (or `$NINFERNO_API_KEY`) or keep `127.0.0.1`.
- **A request body that arrives too slowly is cut off** with 408 `request_body_too_slow`: the body
  must grow by 16 KiB/s over every 10 seconds (`--request-body-min-kib-per-sec`, `0` turns it off).
  On Linux the worker queue is now bounded; past it a connection that has sent a request gets 503
  `server_busy` with `Retry-After: 5`, and `GET /health` is still answered, so slow senders can no
  longer hold every worker and hide the server from a liveness probe. A connection past the queue
  that has sent no bytes yet (one a proxy keeps idle) is closed without an answer, and a large
  request still arriving may see the connection reset after the 503
  ([#540](https://github.com/Brontir/NInferno/pull/540)).
- **JSON bodies are bounded by their number of values:** more than `--max-request-json-values`
  (default 1,000,000) is 400 `request_json_too_large`, refused while the body is parsed, and on
  glibc builds the parse memory is returned to the system afterwards (the value limit applies
  everywhere)
  ([#541](https://github.com/Brontir/NInferno/pull/541)).
- **A grammar compile that no request waits for is cancelled when its slot is needed.** It keeps
  running so a retry finds its cached result, and is cancelled when another request finds every
  slot taken, or when it has run five timeouts in total. Before, four slow patterns could
  hold all compile slots for minutes and every structured request then got 503
  `constraint_compiler_busy` ([#539](https://github.com/Brontir/NInferno/pull/539)).
- **`/metrics`** carries `ninferno_server_info{server_instance_id=...}` and
  `process_start_time_seconds`, so a gateway can see a restart (which empties the cache)
  ([#535](https://github.com/Brontir/NInferno/pull/535)). The Anthropic endpoints take the
  client's `X-Request-Id` like the others
  ([#536](https://github.com/Brontir/NInferno/pull/536)).
- A long Responses context chain no longer overflows the stack when it is released
  ([#534](https://github.com/Brontir/NInferno/pull/534)), and a streamed answer no longer keeps
  every byte it has carried in memory ([#542](https://github.com/Brontir/NInferno/pull/542)).

## Memory and the context cache

The context cache keeps the state of earlier prompts so a repeated prefix is not computed again.
Its second level, the Host tier, lives in pinned system RAM.

- **Several servers started at once:** they now reserve pinned host memory one after another, so
  they no longer run the host out of memory together (4 of 4 came up in our test, before 1 or 2).
  On a host with several GPUs each server's automatic Host tier share is divided by the GPU count,
  so it can be smaller than before. A refused pin halves the automatic size and retries. Pass
  `--host-kv-mib` and `--host-state-slots` for a fixed size. A pin whose size differs from the
  planned one is now an error naming both sizes instead of a second pin
  ([#498](https://github.com/Brontir/NInferno/pull/498)).
- **Shared prefixes:** the default `--max-shared-prefixes` is
  `max(concurrency, 7, Device + Host cached states)`, the last term capped at 256. One long
  conversation can no longer fill every slot and keep a new shared system prompt from being cached.
- **A request that grows the last user message of the previous one** (RAG appending passages, an
  editor resending its buffer) reuses the earlier KV up to where the message diverges, when at
  least 256 tokens can be reused. The reuse stops on a message boundary or leaves at least 17
  tokens to prefill, so a change near the end reuses a little less. It applies
  to models with attention layers only (no Mamba or GDN layers, sliding windows or drafter). On an
  RTX 4060 Ti, Qwen3-8B Q4_K_M, a 20,386-token prompt that grew a 17,473-token one: before, 0
  tokens cached and 8.7 s to the first token; now 17,464 cached and 1.7 s. With
  `--activations exact` the result is byte-identical to a cold prefill
  ([#496](https://github.com/Brontir/NInferno/pull/496)).
- **A small `--kv-lease-window`** no longer caps the answer at a third of the requested length:
  an idle shared prefix is released to let the lease grow
  ([#500](https://github.com/Brontir/NInferno/pull/500)).
- **Faster restarts:** from the third start with the same binary, GPU, driver, model and settings,
  the server skips most of the kernel warm-up (9 to 33 s saved on the cards we timed).
  `NINFERNO_WARMUP_CACHE=0` turns it off.
- **A published NVFP4 or FP8 checkpoint** that cannot fit the GPU is refused before the download.
- **The Hub cache keeps options apart.** A conversion made with an option that changes the artifact
  (`--vocab`, `--layout`, `--name`, `--include`, a resource and others) lives in its own
  `options-<hash>` directory, so a later start without the option no longer reuses it. Existing
  default caches stay valid. A serve `--chat-template` is applied at run time and no longer
  converted in, except for a model that ships no template of its own: that one is converted with
  the file and kept in its own `options-<hash>` directory ([#567](https://github.com/Brontir/NInferno/pull/567)).
- **The plan's speed estimate:** a GGUF's prefill speed estimate shown before the first download
  now agrees with the estimate after conversion. For IQ2/IQ3 GGUF files on RTX 30 and 40
  cards it is closer to measured (within about 5 to 13 %, before 12 to 17 % off).

## Choices that changed

- **The plan prices the benchmark's request mix** (20 short requests of 2048 + 512 tokens to 6 long
  ones), not one short request. Before, decode was priced at a depth of 2304 tokens whatever
  context you asked, so INT8 KV and an f16 state lost to BF16 and f32 at an asked 32K on the Ada
  reference card. Example: RTX 4060 Ti, Qwen3.6-35B-A3B UD-IQ3_XXS: `--max-context 32768` now picks
  KV int8, state f16 and chunk 4096; `--max-context 2560` keeps BF16, f32 and chunk 2048
  ([#509](https://github.com/Brontir/NInferno/pull/509)). Where two candidates are inside the
  speed estimate's resolution, the one with the lower KLD wins
  ([#600](https://github.com/Brontir/NInferno/pull/600)).
- **The MoE prefill chunk on another generation is an estimate, not a pick.** The pick stays 1024;
  the plan JSON now carries `chunk_basis` and `chunk_estimate` (predicted 2048 or 4096 on RTX 50
  cards, to be checked by an A/B)
  ([#659](https://github.com/Brontir/NInferno/pull/659)).
- **The Q2_K estimate on Turing** no longer prices a 128-column tile that the card's 64 KiB of
  shared memory does not hold ([#596](https://github.com/Brontir/NInferno/pull/596)).
- **Register-MMA tile choice for K-quants and i-quants at 17 or more tokens** reads L2 traffic and
  register-bound occupancy, on RTX 30 (sm_86) and RTX 50 (sm_120) cards only, the two generations
  with two measured cards. Against the fastest route, geomean, predicted by the cost model's
  replica on 10 model shapes: RTX 3060 1.165 to 1.068, RTX 3090 1.174 to 1.098, RTX 5090 1.135 to
  1.047, RTX 5070 Ti 1.080 to 1.041 (the RTX 50 pair was not re-timed on the cards); measured with
  the production selector on an RTX 3090: 1.136 to 1.091. The two L2 constants are fitted, one per
  generation, on its two cards together; a third card of the generation takes them as a transfer.
  Ada, Turing and Volta keep the old price ([#499](https://github.com/Brontir/NInferno/pull/499)).
- **An RTX 5090 route table of its own for gemma-4-12B:** three projections used the bands of a
  70-SM part, where the chosen route was 1.70x slower than the best at T=24 (163.8 against
  96.3 us). They are measured now ([#506](https://github.com/Brontir/NInferno/pull/506)).
- **The MTP K/V pair of a hidden size of 5120** runs as two `linear()` calls from 5 to 85 tokens
  on sm_80 and later, where the fused kernel saved no launch and re-read the weights
  ([#565](https://github.com/Brontir/NInferno/pull/565)).
- **The ggml vector kernel for 4 columns** takes a register-bounded twin when that saves a round of
  row groups ([#560](https://github.com/Brontir/NInferno/pull/560)).

## Models and speculation

- `nvidia/Qwen3.6-35B-A3B-NVFP4` converts (19.4 GiB of weights, so it needs a 24 GB or larger
  card). Its MTP layer, stored as a BF16 packed Q/K/gate/V parent of a shape the fused kernel does
  not cover, runs through the generic path; before, `--spec mtp` was refused at start
  ([#548](https://github.com/Brontir/NInferno/pull/548)).
- A DFlash companion drafter published as a GGUF converts with `--with-drafters`.
- **DFlash drafters work with `--rope-yarn-factor`** (before, they were refused). The 35B-A3B
  drafter accepted 22 % of drafts at 75K tokens before and about 60 % now; at about 296K tokens under
  YaRN it is a few percent slower than a window-only layout would be
  ([measurements](../maintainer/dflash.md)). A YaRN rope that a transformers-5 drafter gives only
  in `rope_parameters` is now read as YaRN
  ([#589](https://github.com/Brontir/NInferno/pull/589)).
- **gpt-oss's DFlash drafter** reads only the 4096 context rows it was trained on. On a Tesla GV100
  (gpt-oss-20b MXFP4, 7 drafted tokens, greedy), acceptance at a 20K-token prompt went from 36.3 %
  to 75.6 % and decode from 72-79 to 142-155 tok/s
  ([#563](https://github.com/Brontir/NInferno/pull/563)). The drafter's layers now run over a ring
  of that window, so its KV no longer grows with the context; each cached state slot holds a fixed
  64 MiB for it; at short contexts with many cached slots that costs more memory than the old pages did ([#584](https://github.com/Brontir/NInferno/pull/584)).
- **Drafters on reused conversions:** a drafter whose file was converted again after the model was
  attached is attached again instead of serving plain (on an RTX 5090 gemma-4-12b Q4_K_M served
  185.6 tok/s plain instead of 561.1 with the drafter, on the project's 50-question hard-prompt
  set, one request at a time, [#503](https://github.com/Brontir/NInferno/pull/503)). A cached drafter is reused only if the
  file is the one its report describes ([#576](https://github.com/Brontir/NInferno/pull/576)). A
  drafter the automatic choice wanted but could not get (for example offline) is now a warning with
  the cost and the cure, not a fatal error; `--with-drafters` and `--spec dflash` stay strict
  ([#491](https://github.com/Brontir/NInferno/pull/491)).
- **DSpine drafters** (Qwen3.8-27B-DSpine-b16) are recognized and refused as unsupported. The
  engine does not run them yet, and they are no longer read as plain DFlash
  ([#610](https://github.com/Brontir/NInferno/pull/610)).
- **Chat templates in conversion:** `--chat-template` is baked into a model that ships none
  ([#586](https://github.com/Brontir/NInferno/pull/586)); a `chat_template.jinja` beside a local
  GGUF is its template ([#591](https://github.com/Brontir/NInferno/pull/591)); a kept conversion
  baked with a template is found again ([#595](https://github.com/Brontir/NInferno/pull/595)).
- **An interrupted conversion** removes its temporary files on SIGINT and SIGTERM, and a later run
  sweeps stale ones left by a kill ([#566](https://github.com/Brontir/NInferno/pull/566)).

## Speed

Each gain is one card, one stream, the build just before the change against the change, with
`tools/bench/perf_matrix` unless the text or the linked PR says otherwise. The PR has the full
table, the prediction made before measuring, and the quality checks.

- **V100, MoE prefill on the tensor cores:** gpt-oss-20b (MXFP4) and Gemma 4 26B-A4B (UD-Q4_K_M)
  prefill about 1.4x faster on long prompts ([#437](https://github.com/Brontir/NInferno/pull/437)).
- **V100, MoE decode:** gpt-oss-20b 94.7 to 120.4 tok/s (+27 %), Gemma 4 26B-A4B 70.9 to
  109.8 tok/s (+55 %), plain decode ([#431](https://github.com/Brontir/NInferno/pull/431)).
  gpt-oss's output layer adds +9 % decode (94.7 to 103.2 tok/s, 512 tokens, greedy;
  [#428](https://github.com/Brontir/NInferno/pull/428)).
- **V100, gpt-oss attention on the tensor cores:** prefill of a 20.6K-token prompt 1390 to
  2667 tok/s (1.96x), decode unchanged within 1 %
  ([#443](https://github.com/Brontir/NInferno/pull/443)).
- **Qwen3.5/3.6/3.8 GGUF decode:** +0.9 to 2.5 % on the RTX 4070 Ti, 5070 Ti and 5090, measured on
  Qwen3.5-9B Q4_K_M, plain decode, mean of three 512-token requests. Four small kernels per layer
  are fused into one ([#415](https://github.com/Brontir/NInferno/pull/415)).
- **RTX 2080 Ti, `--kv-dtype bf16`:** Qwen3.5-4B Q4_K_M, 21K-token prompt: prefill 2577 to
  3483 tok/s (+35 %), decode after it 90.4 to 107.5 tok/s (+19 %). Gemma 4 gains only about 2 %
  ([#427](https://github.com/Brontir/NInferno/pull/427)).
- **Prompts of about 100 to 290 tokens, ggml matrix kernel:** it takes the column tile of least
  work (80 and 96 columns added), on RTX 30 cards (#550) and, with a different fixed share, on
  Ada (#597). Time to the first token, Qwen3-8B Q4_K_M, `--no-prefix-reuse`: RTX 3060 144 tokens
  142.0 to 114.4 ms (-19.4 %), 160 tokens -19.1 %, 192 tokens -12.5 %, 256 tokens unchanged;
  RTX 3090 144 to 160 tokens -18.5 to -18.8 %; RTX 4070 Ti 136 to 160 tokens -14.5 %, 176 to 192
  tokens -9.7 to -9.9 %, 208 to 256 tokens within 0.2 %
  ([#550](https://github.com/Brontir/NInferno/pull/550),
  [#597](https://github.com/Brontir/NInferno/pull/597)).
- **Kernel timings** (L2 flushed, per call, not end to end): the 4-column ggml vector kernel,
  Q4_K 3840x15360 at 4 tokens, 68.8 to 48.1 us on an RTX 3090 (#560); the MTP K/V pair at 8
  tokens, 69.6 to 47.1 us on an RTX 4060 Ti (#565). MTP acceptance on an RTX 4090 with
  Qwen3.8-27B UD-Q4_K_M did not shift (2.72 to 2.72 tokens per round at `mtp:2`).
- **Against llama.cpp b12198** (refreshed rows, [#504](https://github.com/Brontir/NInferno/pull/504),
  method in [methodology](../performance/methodology.md)): one stream x1.4 to 1.8 and all streams
  x0.9 to 2.1 against llama.cpp with its own MTP (7 pairs); one stream x1.2 to 2.6 and all streams
  x1.4 to 3.0 where llama.cpp has no drafter file and runs plain (14 pairs). llama.cpp is ahead at
  four concurrent streams with MTP on small Qwen3.5 models (RTX 4070 Ti 9B x0.80, RTX 3060 9B
  x0.82, RTX 4070 Ti 4B x0.95). Against the older NInferno rows, plain decode and prefill gained
  1 to 20 % and speculation at one stream 7 to 30 %; speculation under load lost 6 to 10 % on the
  Qwen3.6 DFlash pairs (an open issue).

## Building

- Blackwell builds (`120a`) now work with CUDA 12.8 as well as 12.9 and 13.x
  ([#538](https://github.com/Brontir/NInferno/pull/538)). The family target `120f` needs CMake
  3.31.8 or 4.0.2 and stops with a message naming that; `120a` builds the same engine
  ([#561](https://github.com/Brontir/NInferno/pull/561)).
- The public headers compile on their own, also with MSVC's library
  ([#551](https://github.com/Brontir/NInferno/pull/551)).
- Decisions are deterministic per binary: the nvcc a binary was compiled with fixes its register
  counts, which differ between 12.8 and 13.x and can move a tile choice (the goldens are keyed by
  the compiled facts)
  ([#568](https://github.com/Brontir/NInferno/pull/568)).

## Not in this release

H100, H200, B200 and B300 engines are built and shipped, but nobody has run them on those cards.
NVFP4 weights run on slower generic kernels below RTX 50. GTX 10 and GTX 16 cards are not
supported. DSpine drafters are refused, not run.

## Under the hood

Most of the other merged work is internal: the route selector, cost model and format facts moved
into named tables and files with golden tests (#484, #494, #497, #609, #630, #641, #646, #608),
committed kernel-facts snapshots so a decision no longer reads the host GPU (#629, #650), audit
tools and a facts-against-driver probe (#605, #645, #674, #678), host-only builds of the decision
code (#660, #664), the MoE and one-profile route selection as named authorities (#636, #677), and a lint workflow in CI (#490).
