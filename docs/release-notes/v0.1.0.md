# NInferno 0.1.0: what to know

The first release. This page lists behaviour you may notice if you tried an earlier build or come
from another server. Flags and defaults are in [serving](../serving.md) and the
[reference](../reference/serving.md).

## Requests and API

- **`tool_choice: "none"`** keeps the tool declarations in the prompt (so the cached prefix is
  reused) but the model can no longer open a call: the syntax's opener token is banned, and the
  answer is text. Before, a model could still write a call, which was cut out and left an empty
  reply.
- **`logit_bias` of `-100` is a ban**: the token loses to every token that is not banned. Offsets
  are in `[-100, 100]`, a token id past the vocabulary is a 400, and a bias of your own on a token
  the server bans (a tool-call opener under `tool_choice: "none"`) is replaced by the ban.
- **A thinking-off request** with no reasoning in its history now renders the earlier assistant
  turns with their (empty) think blocks, so an agent session that adds a user message after many
  tool turns keeps its cached prefix.
- **Regex and JSON Schema `pattern` constraints**: an optional group no longer admits its tail
  without its head (for example `(-[a-z]+)?` could let `1.2rc` through). Output that relied on the
  bug is now refused by the grammar.
- **`repetition_penalty`, `logprobs` and `top_logprobs`** are supported on Chat Completions.

## HTTP

- **HTTP/1.1 requests are checked strictly.** One with no `Host` header (or two), conflicting
  `Content-Length` values, or `Transfer-Encoding` beside `Content-Length` gets 400 and the
  connection closes. Plain HTTP/1.0 clients and any normal client are unaffected. The listen
  backlog is 128.
- **A warning at start** when the server listens on a non-loopback address without an API key.
  Nothing is refused; pass `--api-key-file` (or `$NINFERNO_API_KEY`) or keep `127.0.0.1`.

## Memory and the context cache

- **Host tier**: its automatic size is a share of what the host can pin, divided by the host's
  NVIDIA GPUs, and servers started together pin one at a time. Four servers started at once on one
  host no longer pin the whole limit and get killed. With one GPU nothing changes; with several,
  each server's automatic Host tier is smaller than before. Pass `--host-kv-mib` and
  `--host-state-slots` for a fixed size.
- **Shared prefixes**: the default `--max-shared-prefixes` is
  `max(concurrency, 7, cached Device states + Host state slots)` (at most 256), not
  `max(concurrency, 7)`. A long conversation no longer fills the catalog with prompt ends nobody
  reuses and blocks a new shared system prompt from being cached.
- **Kernel warm-up** is kept across starts with the same binary, GPU, driver, model and settings,
  so a second start skips the width loop, which took 22 to 43 seconds on the cards we timed.
- **A published NVFP4 or FP8 checkpoint** that cannot fit the GPU is refused before the download.
  A GGUF's plan now counts the prefill tail calls its converted artifact has, so the figures you
  see before the first download match the start.

## Models and speculation

- `nvidia/Qwen3.6-35B-A3B-NVFP4` (Model Optimizer export) converts and runs.
- A DFlash companion drafter published as a GGUF converts with `--with-drafters`.
- **DFlash drafters work with `--rope-yarn-factor`** (before, they were refused). The drafter's
  one full-attention layer reads a recent window plus a far memory at every length, which keeps
  acceptance up on long prompts: the 35B-A3B drafter fell from 51 % accepted at 2.5K tokens to 22 %
  at 75K, and holds up much better with this change ([measurements](../maintainer/dflash.md)).
  Qwen3.5 9B at 296K tokens under YaRN is the one case where the older window layout measured better.

## Speed

Gains measured on the cards named, against the build before the change.

- **Volta (V100)**: MoE prefill on the tensor cores, MoE down projection on the R8 kernel (gpt-oss
  +27 %, Gemma 4 26B +55 % decode), the Q8 LM head (+9 % decode on gpt-oss), and one-column
  attention heads on `mma.m8n8k4`.
- **Ampere and Ada**: codebook-IQ and Q4_1 linears pick the int8 tiles at the steps measured for
  them; ga106 and ga102 route tables.
- **Qwen3.5/3.6/3.8 GGUF**: the Q8 gate/beta projections of the gated delta-net layers run as one
  fused launch (0.9 to 2.5 %).
- **Turing**: BF16 K and Q are converted to FP16 once per tile in attention.

## Not in this release

H100, H200, B200 and B300 engines are built and shipped but nobody has run them on those cards.
NVFP4 weights run on slower generic kernels below RTX 50. GTX 10 and GTX 16 cards are not
supported.
