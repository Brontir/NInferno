# Global loads that PDL consumer kernels may issue before griddepcontrol.wait (ACQBULK),
# checked by tools/pdl_sass_audit.py (ctest ninferno_pdl_sass_audit_test).
#
# One rule a line: <regex over the demangled kernel name, without parameters> <offsets>
# Offsets are byte offsets of kernel parameters from the parameter base (c[0x0][0x380]) that a
# pre-wait load's address depends on; '?' allows an address that depends on a loaded value.
# A load before the wait is correct only for memory complete before the producer ran: the call's
# inputs and the weights. Every entry says why; a new pair fails the audit until reviewed here.

# kernel still runs; the router partials, ids and weights are read after the wait.

moe::router_simt_kernel< 12,24

# Generic register-MMA projection, Store epilogue (generic_gemm.cuh): a call with join_previous
# (generic::Call; segmented_projection.cpp sets it on every call after the first) runs alongside
# the call before it and waits only as its last instruction, so every load is before the wait by
# design. The call before it read the same x and writes rows this call neither reads nor writes;
# x (0) with its token stride (8) and K (12), the weight planes - codes (24), high bits (32),
# scales (40) with groups_per_row (48) and scale_tiles (52), NVFP4's per-row-block divisors (64)
# with divisor_rows (72) - and row_begin (76) were complete before that call started. '?' is a
# codebook entry indexed by a loaded weight code. The Add and SwiGLU epilogues, which read the
# output or pair rows, have no wait and never join.
# A decode-width call that does not join (GemmArgs::pdl_prefetch, every epilogue) waits instead
# after the weight ring's first steps: its pre-wait loads are the weight planes above, rows (80) and
# SwiGLU's up_offset (84); x and the AddResidual output are read after the wait (checked in the SASS
# of the NVFP4 w1x8 kernels: every LDG through x's c[0x0][0x380] follows ACQBULK). The audit
# cannot tell that path from the one without pdl_prefetch, where the wait is skipped and nothing
# is a producer's (a plain launch; a joined call as above), so x (0, 8, 12) is listed for every
# epilogue. 160 and 164 (release_next, pdl_prefetch) reach a table-staging address only through the
# thread index the release predicate is combined with. The kernel's last template argument is the
# latency variant (#158, cuobjdump prints it as false / true); the latency kernels' activation
# ring loads x only after the wait, as the staged SwiGLU copy does (#171).
generic::rmma_kernel<.*Epilogue\)0, (false|true)> 0,8,12,24,32,40,48,52,64,72,76,168,172,?
generic::rmma_kernel<.*Epilogue\)[12], (false|true)> 0,8,12,24,32,40,48,52,64,72,76,80,84,168,172,?

# Generic R8 (W8A8 decode, generic_r8.cuh), Store epilogue: joins like the register MMA above and
# waits as its last instruction. It quantizes x (0; token stride 8, K 12) into shared memory and
# streams the weight planes - codes (24), high bits (32), scales (40), groups_per_row (48) - from
# row_begin (76); all complete before the call it joins started. '?' is a codebook grid entry
# indexed by a loaded weight code.
# (The kernel's last template argument is kPre: "Epilogue)0, false>".)
# rows (80) bounds the weight loads of the ring (the IQ3_S codec's address slice reaches it: a
# row past the call's rows loads nothing); it is a call scalar, set before the launch.
# A decode-width call that does not join (GemmArgs::pdl_prefetch, every epilogue) launches as a
# programmatic dependent and waits after its weight ring is filled: its pre-wait loads are the
# weight planes above, rows (80) and SwiGLU's up_offset (84); x is quantized after the wait. As for
# the register MMA, the audit cannot tell that path from a plain or joined launch, so x (0, 8, 12)
# is listed for every epilogue.
generic::r8_kernel<.*Epilogue\)[0-2], false> 0,8,12,24,32,40,48,76,80,84,?
# kPre (the verify-width call on a pre-quantized activation, W4a8Activation after GemmArgs:
# codes 176, scales 184, and for the codecs with a min - K-quants, Q4_1, Q5_1 - sums 192) always
# launches in stream order (r8_launch_tokens), so every load reads memory complete before it
# started; its waits return at once. It reads K (12), the weight planes above and
# the activation planes. The activation offsets move with sizeof(GemmArgs).
generic::r8_kernel<.*Epilogue\)[0-2], true> 12,24,32,40,48,76,80,84,184,192,200,?
